## Documentation requirements

- Generate documentation in Russian.
- Verify documented API behavior against the actual source code.
- Do not invent endpoints, HTTP methods, parameters, request or response fields, status codes, examples, or behavior.
- Read the existing README before preparing changes.
- Preserve unrelated sections and existing documentation structure.
- Update only documentation affected by the source code changes.
- Return the complete updated contents of each changed documentation file.
- If no documentation update is necessary, return an empty `changes` array and explain why in `summary`.
- Do not modify files or create Git commits through MCP tools. The downstream workflow handles writing files and committing changes.

## Required output format

Return exactly one valid JSON object:

  "unverified_information": []

## Output rules

- `summary` must be a string.
- `changes` must be an array of objects, not an array of strings.
- Every object in `changes` must contain `file_path`, `content`, and `reason`, all as strings.
- `file_path` must be relative to `/workspace/docs` and must match the repository supplied by the webhook.
- `content` must contain the complete updated file, not a diff or partial excerpt.
- `reason` must explain why the file needs updating.
- `unverified_information` must be an array of strings. Use an empty array if all relevant facts have been verified.
- Ensure that the response is valid JSON, with quotation marks, backslashes, and newline characters escaped correctly.
- Do not include Markdown code fences, comments, or any text outside the JSON object.
